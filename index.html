    How to use it with Copilot

    1. Download papers and data and unzip the pack – or download single files below.
    2. Pick a test idea below, or any paper or data file that fits your use case.
    3. In Copilot Chat, upload the paper or data file you need for your prompt.
    4. For a data file, first ask Copilot to describe it: columns, units, missing-value codes. Check this against the file.
    5. Then run your use case – and check every number, quote and citation against the data or the PDF.

    Copilot reads a PDF as text, so tables, figures and equations are easily misread – check them in the paper itself. If Copilot does not accept a .txt file, rename it to .csv or paste its content into the chat.

      Academic Extensions & Tools

      Tools commonly used in academic work, mapped to the research phases – for orientation, not recommendations. They complement Copilot rather than replace it: subject databases, reference managers and analysis software do things a general assistant cannot. Many of them can also be connected to Copilot, most flexibly through the Model Context Protocol (MCP), an open standard that lets an assistant call another tool and use its results.

      Example: a Copilot Studio agent connected to scite’s MCP server can check, while you draft a literature review, whether later studies support or contrast a finding you cite – and answers with the actual citation statements and DOIs instead of guessing.

      Ratings: by students at a German university, 2024/25 (greyed out with fewer than three ratings); tools without a rating were added for this workshop. MCP official server from the provider · MCP community server, review before use · “Copilot Studio” = remote server that can be added there directly · Microsoft 365 other ways the tool connects to Copilot, Word, Teams, Outlook or Power Automate.

      How to connect a tool to Copilot via MCPThree routes, from simple to flexible – and what to check first.

      1 · Ready-made connectors

      With a Microsoft 365 Copilot licence, IT can switch on ready-made Copilot connectors – for research, for example Consensus, scite, PubMed, DeepL and Notion. Many of them use MCP in the background. Nothing to build – ask your IT team whether they are available.

      2 · Your own agent in Copilot Studio

      1. In Copilot Studio, create an agent and open Tools → Add a tool → New tool → Model Context Protocol.
      2. Enter a name, a short description (Copilot uses it to decide when to call the tool) and the server URL from the provider’s documentation.
      3. Choose how to sign in: none, API key or OAuth 2.0. With OAuth, each researcher uses their own account.
      4. Add instructions such as “cite DOIs, never invent sources”, test the agent, then publish it to Teams and Microsoft 365 Copilot and share it.

      3 · Code and analysis

      GitHub Copilot in VS Code connects to MCP servers directly – including local ones such as Zotero or jamovi.

      Without MCP

      Many tools already work inside Microsoft 365: reference managers cite while you write in Word (Zotero, EndNote, Mendeley, Citavi, Paperpile), note-takers join Teams meetings (Otter, Sally), and some offer Power Automate connectors. Filter by “Microsoft 365 integration” below.

      Before you start

      • Copilot Studio only connects to remote servers (HTTPS). Local community servers need VS Code or a desktop assistant.
      • Building and publishing agents may need additional licences; IT usually approves agents and can restrict connectors.
      • Your prompts and inputs go to the tool provider. Check your university’s data rules; never send unpublished or personal data to an unvetted server.
      • Community servers are not maintained by the provider – review the code and permissions first.
